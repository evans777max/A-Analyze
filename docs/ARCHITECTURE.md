## 数据流

1. **盘中**：浏览器打开页面 → 直连行情源轮询 → 本地实时计算四层评分（不写任何远端）。
2. **收盘后**：Actions 定时触发 snapshot → 拉收盘行情与日K → 用同口径模型重算全池评分 → 校验通过后 commit 进 `data/history.json`。
3. **页面读取历史**：页面启动时 fetch `data/history.json` 渲染评分轨迹（file:// 打开时自动降级为本机 localStorage 记录）。
4. **审计**：人工运行 audit/xmarket 脚本，结论沉淀到 docs 与周报。

## 关键文件职责

| 文件 | 职责 |
|---|---|
| `index.html` | 全部前端：行情接入、四层评分、警示规则、自选池管理、评分轨迹渲染 |
| `scripts/snapshot.mjs` | 收盘评分快照（复刻页面模型，**改模型必须两处同步**，由 validate-repo 校验） |
| `scripts/audit.mjs` | 模型体检：按历史日重算分层评分，计算 IC / 分组收益 / 惩罚项有效性 |
| `scripts/xmarket.mjs` | 跨市场传导：隔夜美股→A股跳空/日内、日韩并发性、个股锚→板块篮子 |
| `scripts/backfill.mjs` | 一次性历史回填（v3.x 口径，已冻结，见文件头注释） |
| `scripts/validate-repo.mjs` | 仓库自检：版本一致性、模型口径锚点、history.json 质量、隐私模式扫描 |
| `data/history.json` | 评分历史（唯一持久化数据），schema 见 MODEL_CARD |
| `data/model-meta.json` | 版本元数据与模型纪元（epoch）边界 |
| `.github/workflows/snapshot.yml` | 每日快照管线（双 cron + 并发保护 + 提交前校验） |
| `.github/workflows/validate.yml` | push/PR 静态校验（语法 + validate-repo，不触发行情抓取） |
| `weekly/` | 周度复盘存档（HTML / MD / PDF 三格式） |

## 设计原则

- **单文件前端**：`index.html` 不依赖构建工具与运行时包，保证 GitHub Pages、任意静态托管、本地双击三种方式行为一致。
- **数据与代码同仓**：历史评分随仓库版本化，任何人可复核任意一天的记录何时写入、是否被改动。
- **同口径双实现 + 机器校验**：页面（浏览器 JS）与快照（Node）各持一份模型实现，靠 `validate-repo.mjs` 的口径锚点检查防漂移；长期方案见 ROADMAP 的 model-core 提取。
- **审计可复跑**：所有研究结论的生成脚本入库，数据源为公开行情，任何时点可重跑复核。
