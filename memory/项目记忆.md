## §6 环境与工具链备忘（泛化脱敏版，2026-08-10 自私有层迁移）

**行情数据源**
- 腾讯 `qt.gtimg.cn` 返回 GBK 编码，Node 侧用 `TextDecoder('gbk')` 解码；字段 30=时间戳、37=成交额(万)、38=换手、7/8=外盘/内盘
- 新浪日K `datalen` 可取 260+ 根（覆盖整年）；**收盘后当日 bar 有延迟**，需用 qt 实时收盘价兜底补当日
- 东财接口在部分网络环境不可达，页面已按可用因子自动降级；美/日/韩指数日K可用 Yahoo chart API（`query1.finance.yahoo.com/v8/finance/chart/`）
- 北交所已整体迁至 920 代码段，旧 83/87/43 段代码返回停牌快照
- 北交所收盘价由 14:57-15:00 集合竞价决定，竞价盘薄，数百手即可使收盘价偏离连续竞价尾价 1%+

**GitHub / CI**
- Actions 定时任务常延迟 2-3 小时（已用双 cron + 手动 dispatch 兜底，workflow 级并发保护）
- `GITHUB_TOKEN` 的 bot 提交不会触发其他 workflow（防递归机制）——因此快照数据的校验放在管线内"先校验后提交"步骤，而非依赖 push 触发
- GitHub 网页不渲染 HTML 文件（只显源码）；其内置 PDF 预览对 chromium 生成的中文子集字体 PDF 可能报错（文件本身无损，下载后正常）——网页分发走 Pages
- GitHub Pages 新子域名首次启用有 CDN 传播窗口，期间部分节点返回 404 且可能被缓存约 10 分钟，加查询参数可绕过

**验证方法论**
- 线上可达性结论必须区分"服务端在线"与"目标地区用户可达"：本机网络出口地区可能与目标用户不同，仅凭本机测试（尤其 IP 直连绕 DNS）会产生系统性误判——曾因此误判过页面托管平台的内地可用性
- 盘中记录的数字必须在收盘后用快照数据复核（盘感与盘中读数会出错）
- Playwright：`file://` 下页面 fetch 本地 JSON 会失败（页面需优雅降级）；等待外部资源用 `load` 而非 `networkidle`（外链可能挂起）

**Windows/PowerShell（本项目脚本编写注意）**
- PowerShell 5.1 将无 BOM 的 UTF-8 `.ps1` 按 ANSI 解析：脚本含中文/全角字符会乱码甚至解析失败——临时脚本优先用 Node/Python，或保持纯 ASCII
- PowerShell 管道/重定向会破坏二进制与 UTF-8 流：下载二进制用 `curl.exe -o` 或由 Node/Python 直接抓取，勿经由 shell 管道
- 新写入的脚本文件立即执行可能遇到可见性竞态：执行报"文件不存在"时等待数秒重试即可
